## E8 A：真实 BuildChecker 基线与未变化输入复用

### 独立预期与输入

C0 样例的 Makefile 声明 `main.o: main.c unused.h`，但 `main.c` 实际包含 `config.h`。因此独立预期为：

- 实际对象依赖：`main.o -> config.h, main.c`；`helper.o -> helper.c`。
- 发现：`MISSING main.o config.h`；`REDUNDANT main.o unused.h`。
- 未变化时两个对象目标复用历史图。

### GCC 投影结果

```text
actual   = {'main.o': ['config.h', 'main.c'], 'helper.o': ['helper.c']}
declared = {'main.o': ['main.c', 'unused.h'], 'helper.o': ['helper.c']}
findings = [
  {'type': 'MISSING',    'target': 'main.o', 'dependency': 'config.h'},
  {'type': 'REDUNDANT',  'target': 'main.o', 'dependency': 'unused.h'}
]
```

### 真实 BuildChecker 结果

- `$OUT/buildchecker/findings.json`：`status=SUCCEEDED`。
- 检测器：`BUILDCHECKER_TEACHING 0.2.0-teaching`。
- trace id：`e6-dbfe9ddb93344b97b56ce0e0f7f3d4d3`。
- observed targets：`app`、`helper.o`、`main.o`。
- 耗时：`127 ms`。
- 原始证据：`buildchecker/trace/t.14` 第 579 行显示 `openat(..., "config.h", O_RDONLY...)`；`buildchecker/make-db.txt` 第 1044 行显示 `main.o: main.c unused.h`。这同时证明 config.h 被读取、但未在 main.o 声明中列出。
- baseline 的 `baseline_source` 写为 `BuildChecker actual-graph.json projected to object targets`，没有把 GCC 投影冒充成 BuildChecker 原始结果。

### 未变化增量复用

```text
reused   = ['main.o', 'helper.o']
refreshed = []
actual / findings 与 baseline 完全一致
```

结论：历史图来源为本次真实 BuildChecker；未变化输入下两个对象目标复用，且 findings 未变化。

## 论文机制对应、教学简化与扩展计划

- 对应论文机制：用实际观测到的对象依赖（observed actual graph）对照 Makefile 声明（declared graph），识别 MISSING / REDUNDANT，并在输入未变化时复用历史图。
- 教学简化：只支持两个固定对象目标（`main.o`、`helper.o`）、顶层 C/H 文件、简单显式规则、简单变量和受限 CFLAGS（`-O0`、`-O1`、`-O0 -DMODE=1`）。
- 保守策略：缓存 key 包含所有本地 C/H 预处理指令、配方、flags 和编译器版本；任一头文件指令变化都会刷新两个目标。这牺牲部分增量精度，换取不漏边。
- 扩展计划：可在后续实验中改为按目标失效、支持更多 Make 语法，并与课程 B 组做 E12 的真实服务联调；本阶段不声称完成 E12。

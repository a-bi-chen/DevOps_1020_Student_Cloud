# ADR：E13–E14 交叉测试与四容器运行决策

- 编号：ADR-241880375-E13E14-001
- 日期：2026-11-17
- 作者：张海洋 241880375
- 小组/轨道：A09 / A 组

## 问题

E13 要在已集成的 E11–E12 系统上处理开发阶段未知的输入和故障，E14 要把四项能力拆成四个独立 HTTP 服务并准备候选发布。需要解决：

1. 对方项目位于其仓库子目录时，如何在不越界的前提下让四个能力作用于实际项目。
2. 跨人/跨机传递的增量报告如何防止字节被替换。
3. 对方 Makefile 的合法写法超出本组原显式 profile 时，如何扩展而不放宽为任意配置。
4. 共享云机上端口被队友容器占用时，如何留下真实 E2E 证据又不违反“不清理他人容器”。
5. CI 中宿主机与容器属主不同，Git 如何安全读取工作目录。

## 候选方案

1. 要求对方把项目复制到仓库根目录，或手工改请求路径。
2. 只校验报告 JSON 中的 commit，不校验传输字节。
3. 允许任意 CFLAGS，或直接判定对方项目“不支持”。
4. 停止占用端口的队友容器，或改用不同端口但不记录。
5. 在容器内执行 `git config --global --add safe.directory /course`，或通过环境变量限定信任。

## 采用方案与理由

- **采用 `project_subdir`**：请求只接受仓库内相对路径；绝对路径、`..`、解析后越界和不存在目录全部拒绝。实际项目根用于 BuildChecker、EChecker、DRAFT、MDFixer，仓库根只用于 checkout。这样既能测试对方真实布局，又不复制或改写对方仓库。
- **采用 `fixed_report_sha256`**：读取报告前先对文件字节计算 SHA256；不匹配返回 `ARTIFACT_HASH_MISMATCH`。字段可选，保持旧请求兼容。
- **采用显式 profile 扩展**：解析 `=`、`?=`、`:=`，只把 B 项目实际使用的 `-std=c11 -Wall -Wextra -Werror` 加入白名单。未知 flags 继续拒绝，避免“为了通过而放开一切”。
- **采用端口环境变量 + 本地覆盖件**：提交的 `compose.yaml` 保持 `127.0.0.1:18081–18084`；云机因队友容器占用 `18081`，本地证据用 `work/e14-compose.local.yaml` 将 BuildChecker 映射到 `18091`，并记录原因。CI 用规范端口验证。
- **采用容器内 Git 环境变量**：`GIT_CONFIG_COUNT/KEY_0/VALUE_0` 仅对容器内 Git 进程生效，不污染宿主全局配置；服务自身的 `/course/data`、`/course/work` 路径限制保持不变。

## 后果

- 正面：对方项目不需要改写；报告篡改可被独立发现；CI 与本地共享主机都能复现；证据能区分“规范端口 CI”和“共享主机临时端口”。
- 负面：`validate()` 仍保留课程 `1 → 2` 断言，B 项目 `hello E3` 不进入修复验证全链路；这是本轮明确记录的适配边界，而不是静默跳过。
- 负面：端口环境变量属于教学包之外的少量增强，需在报告中公开，不能伪装成教师原文件行为。

## 未采用

- 未停止 `friendly_wright` 等队友容器。
- 未把报告 JSON 的 commit 校验当作传输哈希校验。
- 未把未知 flags 全部放行。
- 未在 B 组回执缺失时创建 `v0.9-rc`。

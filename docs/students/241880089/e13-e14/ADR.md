# ADR：E13–E14 个人执行取舍（241880089）

## ADR-1 新增 `labs/e13` 适配入口，而不是改 `labs/e11e12` 或 B09 仓库

**背景与约束**：B09 的真实项目位于 `fixtures/e11e12-b1-real` 子目录，`Makefile` 使用 `CFLAGS ?= -std=c11 -Wall -Wextra -Werror`。A09 官方入口以仓库根为项目根，EChecker 的 flags 白名单只接受 `-O0`、`-O1`、`-O0 -DMODE=1`。

**选择与替代方案**：

- 选择：新增 `labs/e13/run_crosscheck.py`，只做“子目录定位 + E13 flags profile”两项适配；BuildChecker `full_check` 原样调用，EChecker 算法不变。
- 替代 1：改 `labs/e11e12/pipeline.py` 的默认项目根。否决，因为会改变 E11–E12 已验收入口的语义，影响其他人和历史证据。
- 替代 2：要求 B09 把项目移到仓库根或改 `Makefile` 的 flags。否决，因为会改写对方提交，使 `30ffe4c…` / `a7e3b64…` 两个固定 SHA 失去意义。

**代价与覆盖范围**：多了一条受约束的适配路径；非 B09 项目仍会明确报 `UNSUPPORTED_PROJECT` / `UNSUPPORTED_FLAGS`，不会静默放过。

**验证**：`labs/e13/run_crosscheck.py` 在 `30ffe4c…` / `a7e3b64…` 上 `SUCCEEDED`；94 项证据哈希全部通过；官方入口的三种失败日志保留在证据包内。

## ADR-2 保留官方入口失败证据，而不是只报告适配后的成功

**背景**：E13 手册要求“输入超出适配范围时如实标记，不能写成通过”。

**选择**：先分别以子目录、仓库根、直接 `scan()` 三种方式调用官方入口，保存真实错误码和日志（`official-entry-*.log`、`entry-probes.json`），再用适配器执行正式检测。

**理由**：只留下成功结果会掩盖“官方入口原本不能运行”的事实，无法让 B09 或教师复现适配边界。

**后果**：证据包里同时存在失败与成功记录；报告明确区分“官方入口失败”与“适配后检测成功”。

## ADR-3 个人范围只覆盖 E13 C1，不重复 C2–C8、H1–H3 与 E14

**背景**：组级 C2–C8、H1–H3 与 E14 四容器已由 241880374 / 241880375 执行并归档；个人分支的作用是证明本人环境可独立复现一部分结论，而不是复制等价证据。

**选择**：个人只执行 A 侧 C1（B09 真实项目检测）及其 2026-11-24 复跑。

**理由**：C1 同时覆盖子目录适配、BuildChecker 全量、EChecker 增量与真实命令链，是个人环境可独立复现的最小完整切片。

**后果**：个人报告不声称 C2–C8、H1–H3、E14 由本人完成；组级门禁仍以组级记录为准。

## ADR-4 B09 合并后复跑但不移动 `v0.9-rc`

**背景**：B09 在 PR #20 合并（`298ff136…`）后于 2026-11-24 复跑并向 A09 发来补充核验消息；`v0.9-rc` 已指向 `ee6f7da9…`。

**选择**：用相同 Base/Target 在服务器复跑 C1，生成新证据目录和 94 项清单；不修改 `v0.9-rc`，不替换 2026-11-23 已签收的原交付包。

**理由**：复跑只回答“统一代码是否改变固定项目提交的检测结论”，不构成新的交付或发布；移动标签会破坏已签收对象的可追溯性。

**后果**：新证据与旧签收并存；报告明确写出“本次复跑不改变原交付包”。

# ADR：E13–E14 个人执行取舍

## ADR-1 用 `project_subdir` 扩展适配器，而不是要求 B09 改组结构

背景：B09 的真实项目位于 `fixtures/e11e12-b1-real` 子目录，且 Makefile 使用 `CFLAGS ?=`、`TARGET :=`。原实现在仓库根目录查找 `main.c`/`helper.c`，并且只识别 `CFLAGS =`。

决定：在 `pipeline.py` 增加 `project_subdir`（拒绝绝对路径与 `..`，必须落在克隆仓库内），在 `lab.py` 支持 `?=`/`:=`，并把 `-std=c11 -Wall -Wextra -Werror` 纳入允许的 CFLAGS。

理由：E13 手册要求“超出适配范围先补适配，再下算法结论”。改动对方仓库会破坏其 E11–E12 证据链，也会让两个原始提交号失去意义。

后果：适配器多了一条受约束的输入路径；不适配的项目仍会明确报 `UNSUPPORTED_PROJECT` / `UNSUPPORTED_FLAGS`，不会静默放过。

## ADR-2 个人复跑选择 C1 + H1–H3 + E14，而不重复 C2–C8

决定：个人分支只覆盖 C1（对方真实项目）、三个教师未知项目、E14 四容器与故障恢复。

理由：C2–C8 的组级证据已经完整，由张海洋执行并归档；重复执行只产生第二份等价证据，不增加信息量。个人复跑的目的是证明本人环境可独立复现，这三项足以覆盖适配、算法、编排与故障路径。

后果：个人报告不声称 C2–C8 由本人完成，组级门禁判定仍以组级记录为准。

## ADR-3 端口冲突时停自己的遗留容器，而不是改端口

背景：`127.0.0.1:18081` 被本人 11 月 16 日遗留的 `serve` 容器占用。

决定：`docker stop` 该容器后，按 `compose.yaml` 的规范端口启动。

理由：改端口会让个人证据与 CI 使用的端口不一致，降低可比性；该容器属于本人，不属于其他组员或全组共享服务。

后果：遗留容器被停止（未删除），需要时可 `docker start` 恢复。
